Resolved Distribution Model

The SRS flags how members with different participation levels receive distributions as the single most important design issue. Each scheme selects one of three modes — the draw and distribution engines branch on it, and an entitlement-balance view prevents over-distribution.

Recommended default: equal_rounds

A fixed round_value (typically the smallest member target) is paid per round. A member wins exactly enough rounds to satisfy their target, then is excluded. Total distributed always equals total collected equals the sum of targets — so the books balance by construction.

traditional_pool
Full collected pool to one winner. Classic rotating Ekub; each member wins once.
equal_rounds
Fixed round_value per round. Best for mixed Full / Half / Quarter targets.
target_entitlement
min(remaining_target, available pool) per round. For variable or irregular collections.

The traditional rotating Ekub is the traditional_pool special case. Full details and a worked example are in the Technical Design PDF.

Quick Start

Load the schema and seed into a PostgreSQL 15+ database to explore the model.

  1. Create the database and a least-privilege application role.
  2. Load the schema (creates tables, constraints, RLS policies, and audit triggers):
psql -d eams -f database/eams_database_schema.sql
  1. Load the demonstration dataset (demonstration environments only — never production):
psql -d eams -f database/eams_seed_data.sql
  1. Verify the books balance — every posted journal entry must show balance_difference = 0:
SELECT * FROM v_journal_balance_check;

For the full Docker-based deployment, TLS, backups, and the go-live checklist, see the Deployment Guide.
